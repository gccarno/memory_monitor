# memwatch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Windows memory monitor that logs per-app memory and usage over days. Add an on-demand local report that ranks what to stop, each with a reason, and buttons that really stop apps and disable their startup entries.

**Architecture:**
- A background **logger** samples every 60 s and writes to SQLite.
- A short-lived **report server** (localhost, token-protected) reads SQLite, builds suggestions, serves one HTML page, and executes actions. Admin-only actions go through a UAC-elevated runner that accepts a fixed whitelist of operations.
- The logger and the report share **only** the database and the `models` dataclasses. This keeps the Rust fallback for the logger clean.

**Tech Stack:** Python 3.11.9, `psutil`, `pywin32`, stdlib `sqlite3` / `http.server` / `tomllib` / `ctypes`, `pytest`. The page uses vanilla HTML/JS with inline-SVG sparklines.

**Spec:** `docs/superpowers/specs/2026-11-05-memory-monitor-design.md`. Read it before starting any task.

## Global Constraints

- Windows 11 only. Python 3.11. Runtime dependencies are `psutil` and `pywin32` only. The dev dependency is `pytest`.
- Use a venv at `.venv`. All commands use `.venv\Scripts\python`.
- Data dir: `%LOCALAPPDATA%\memwatch\`. DB: `memwatch.db`. Optional config: `config.toml`. Log: `logger.log`.
- Sampling interval: 60 s. Retention: 30 days (prune older samples automatically).
- Logger working-set cap: ~50 MB. It is measured and shown in the report. Over the cap triggers the Rust-logger fallback; that is not part of this plan.
- The logger runs without admin. Processes it cannot fully read are marked `limited`; nothing is guessed.
- Data stays local. The only network traffic is the report on `127.0.0.1`.
- Nothing is ever killed or changed without an explicit click in the report.
- Windows core processes and Defender, memwatch itself, and the report's launching process tree are never suggested and never acted on.
- Optional Microsoft components **are** suggestable, with a caution label.
- Never offer `disabled` for a service that has running dependents; offer `manual` only.
- "Stop now" on windowed apps sends only WM_CLOSE. A force kill is a separate, second click.
- Disabling startup uses `StartupApproved` (Run, Run32, StartupFolder), packaged-task `State`, `schtasks /DISABLE`, or a service start type of Manual/Disabled. Every change is recorded for Undo.
- Report "before several days" must say `Based on X hours of data` when fewer than 72 observed hours exist.

## Review Focus

1. **The laptop was off or asleep, or the logger wasn't running.** "Not used in N days" must count only observed time. Otherwise, after a week away, everything looks idle. Pinned in Task 7 (`test_idle_counts_only_observed_time`).
2. **PID reuse between page load and click.** An action must verify `(pid, create_time)` and never touch an unrelated process that inherited the PID. Pinned in Task 8 (`test_stop_skips_reused_pid`).
3. **The app is already closed when the button is clicked.** Return `already_stopped`, not an error. Pinned in Task 8 (`test_stop_on_vanished_app`).
4. **UAC prompt declined.** Return `declined`, change nothing, and record no Undo entry. Pinned in Task 8 (`test_disable_startup_declined_records_nothing`).
5. **A process exits or denies access in the middle of a probe.** Skip it or mark it `limited`; the logger tick must not crash. Pinned in Task 3 (`test_snapshot_survives_vanishing_and_denied`).

### Task 2: Database

**Files:**
- Create: `src/memwatch/db.py`
- Test: `tests/test_db.py`

**Interfaces:**
- Consumes: models from Task 1.
- Produces:
  - `connect(path: Path) -> sqlite3.Connection`: creates parent dirs, `PRAGMA journal_mode=WAL`, creates the schema idempotently.
  - `write_tick(conn, system: SystemSnapshot, apps: list[tuple[AppGroup, UsageFlags]]) -> None`: inserts one `system` row and one `samples` row per app. Upserts `apps`:
    - `last_seen = ts`
    - `last_used = ts` if foreground
    - `last_active = ts` if active
    - `has_windows_ever |= has_windows`
    - label, kind, microsoft, services and limited are refreshed
    - `first_seen` is set only on insert
  - `prune(conn, now: int, retention_days: int) -> int`: deletes `samples` and `system` rows older than the cutoff, and `apps` rows not seen since then. Returns the number of sample rows deleted.
  - `latest_system(conn) -> SystemSnapshot | None`
  - `system_ticks_since(conn, since: int) -> list[int]`: ascending ts values of `system` rows. This is the "observed time" clock.
  - `app_history(conn, since: int) -> dict[str, list[SampleRow]]`
  - `all_apps(conn) -> list[AppRecord]`
  - `latest_groups(conn) -> dict[str, tuple[int,int,int]]`: app_key → (ts, private_bytes, working_set) at the latest tick.
  - `replace_startup(conn, entries: list[StartupEntry]) -> None`, `startup_entries(conn) -> list[StartupEntry]`
  - `record_action(conn, rec: ActionRecord) -> int`, `list_actions(conn, include_undone: bool = False) -> list[ActionRecord]`, `get_action(conn, id: int) -> ActionRecord | None`, `mark_undone(conn, id: int) -> None`

Schema:
- `samples(ts INTEGER, app_key TEXT, private_bytes INTEGER, working_set INTEGER, n_procs INTEGER, foreground INTEGER, active INTEGER, PRIMARY KEY(ts, app_key))` with an index on `app_key, ts`.
- `system(ts INTEGER PRIMARY KEY, …SystemSnapshot fields)`
- `apps(app_key TEXT PRIMARY KEY, label, kind, microsoft, first_seen, last_seen, last_used, last_active, has_windows_ever, limited, services_json)`
- `startup(...StartupEntry fields)`
- `actions(id INTEGER PRIMARY KEY, ts, app_key, action, entry_json, before_json, undone INTEGER DEFAULT 0)`

### Task 3: Probe (processes, system, windows, services)

**Files:**
- Create: `src/memwatch/probe.py`
- Test: `tests/test_probe.py`

**Interfaces:**
- Produces:
  - `snapshot_processes() -> list[ProcInfo]`: `psutil.process_iter`.
    - `private_bytes = memory_info().private`, `working_set = memory_info().wset`
    - `cpu_s = user + system`; `io_bytes = read_bytes + write_bytes`
    - `NoSuchProcess`: skip the process.
    - `AccessDenied` on any field: set that field to None and `limited=True`. Memory fields fall back to 0.
    - Cache `exe`, `cmdline` and `cwd` by `(pid, create_time)` in a module-level dict pruned each call. This keeps per-tick cost low.
  - `system_snapshot(ts: int) -> SystemSnapshot`:
    - `GetPerformanceInfo` (psapi via ctypes): CommitTotal, CommitLimit, KernelPaged, KernelNonpaged, times PageSize.
    - `psutil.virtual_memory()` for total/available.
    - `compression_ws` = working set of the process named `Memory Compression`, or None if denied.
    - `boot_time = int(psutil.boot_time())`, `logger_ws=None`.
  - `foreground_pid() -> int | None`: `GetForegroundWindow` + `GetWindowThreadProcessId`.
  - `window_pids() -> set[int]`: `EnumWindows`, collecting windows that are `IsWindowVisible`, have a non-empty title, and are not cloaked (`DwmGetWindowAttribute` DWMWA_CLOAKED).
  - `seconds_since_input() -> float`: `GetLastInputInfo` vs `GetTickCount64`.
  - `services_by_pid() -> dict[int, list[ServiceInfo]]` and `all_services() -> list[ServiceInfo]`: via `psutil.win_service_iter()`. Map `start_type` `auto`→`automatic`.

### Task 4: Grouping into apps

**Files:**
- Create: `src/memwatch/grouping.py`
- Test: `tests/test_grouping.py`

**Interfaces:**
- Consumes: `ProcInfo`, `ServiceInfo`, `AppGroup`, `Config`.
- Produces:
  - `suite_from_path(path: str | None, name: str, cfg: Config) -> tuple[str, str, bool]`, returning `(app_key, label, microsoft)`. Also used by `startup.py` to map entries to apps.
  - `group_processes(procs: list[ProcInfo], services: dict[int, list[ServiceInfo]], cfg: Config) -> dict[str, AppGroup]`
  - `group_for_key(app_key: str, cfg: Config) -> AppGroup | None`: fresh probe + group, then lookup. The server and actions use it.

Rules, applied in this order:
1. **Protected.** A process is protected if its lowercase name is in `protected_names`, or it is `svchost.exe` and any hosted service (lowercased) is in `protected_services`, or it is pid 0 or 4. All protected processes go into one group: `app_key="protected:windows"`, label `Windows core`, kind `protected`.
2. **Instances.** Each of these is its own group, keyed `f"{type}:{pid}:{int(create_time)}"`. Their descendants join them.
   - `claude-cli`: name `claude.exe` and exe contains `\.local\bin\`. Label: `Claude Code session (started Oct 30 20:07)`, plus ` — <cwd>` when cwd is known.
   - `python`: name `python.exe`/`pythonw.exe`. Label: `Python: <first .py arg basename or "-m module"; otherwise "interpreter">`.
   - `emulator`: name starts `qemu-system-`. Label: `Android emulator (<value after -avd>)`.
3. **svchost services (non-protected).** Key `service:<name lower>`. For several services, key the names sorted and joined with `+`. Label: the display name(s). kind `windows`, `microsoft=True`, `services` = names.
4. **Inheritance.** A process whose parent is in the snapshot, whose parent's name is **not** in `shell_parent_names`, and which is not rule 1–3 joins its parent's group. Resolve top-down so chains work.
5. **Suites.** Remaining roots, including non-svchost service processes (they add their service names to `services`), use `suite_from_path(exe, name)`:
   - `suite_overrides` substring match on the lowercased path → label.
   - `\windowsapps\<pkg>_...\` → package name before the first `_`. `microsoft` is True when it starts with `microsoft`.
   - `\program files\<v>\`, `\program files (x86)\<v>\`, `\appdata\local\programs\<v>\`, `\appdata\local\<v>\`, `\appdata\roaming\<v>\` → `<v>`. A `<v>` of `Microsoft` uses the next folder instead (e.g. `Microsoft OneDrive`), with `microsoft=True`.
   - `\windows\` → `windows:<name lower>`, label = name, kind `windows`, `microsoft=True`.
   - Exe unknown (limited) → label = name without `.exe`.
   - Key: `suite:<label lower>`, unless it is the `windows:` form.
6. **Totals.** Groups sum `private_bytes` and `working_set`, collect `pids` as `(pid, create_time)`, and OR `limited`.

  - `Suggestion(app_key:str, label:str, kind:str, private_bytes:int, working_set:int, typical_private:int, last_used:int|None, idle_observed_s:int, reasons:list[str], reason_codes:list[str], has_windows:bool, caution:str|None, limited:bool, startup:list[StartupEntry], service_modes:list[str])`.   - `AppSummary(app_key:str, label:str, private_bytes:int, last_used:int|None, autostart:bool, spark:list[int])`. `spark` holds up to 48 hourly-max private_bytes points.
  - `Report(now:int, system:SystemSnapshot|None, observed_hours:float, partial_note:str|None, reclaimable:int, suggestions:list[Suggestion], apps:list[AppSummary], kernel_note:str|None, uptime_s:int, logger_ws:int|None, logger_over_cap:bool, undo:list[ActionRecord])`
- Produces, in `suggest.py`:
  - `build_report(conn, cfg: Config, now: int, exclude_keys: set[str] = frozenset(), dependents: Callable[[str], list[str]] = default_dependents, service_desc: Callable[[str], str] = default_service_desc) -> Report`
  - `default_service_desc(service: str) -> str`: the service description via `win32service.QueryServiceConfig2(..., SERVICE_CONFIG_DESCRIPTION)`, or `""`.
  - `fmt_size(b: int) -> str`: `"4.0 GB"` at ≥1 GiB, else `"600 MB"`.
  - `fmt_dur(s: int) -> str`: `"N minutes"` under 1 h, `"N hours"` under 48 h, else `"N days"`. Singulars: `"1 minute"`, `"1 hour"`.
  - `default_dependents(service: str) -> list[str]`: running dependent services via `win32service.EnumDependentServices`.

Rules (the history window is the last 30 days):
- **Observed time.** `ticks = system_ticks_since(conn, since)`. `idle_observed_s = interval × (number of ticks with ts > (last_used or first_seen))`. `observed_hours = len(ticks) × interval / 3600`. When `observed_hours < partial_hours`, `partial_note = f"Based on {fmt_dur(...)} of data"`.
- **Candidates.** Apps present at the latest tick, excluding `protected` kind and `exclude_keys`. The server computes `exclude_keys` (Task 9).
- **Reason codes and exact sentences** (`size = fmt_size(private_bytes)`, `idle = fmt_dur(idle_observed_s)`):

  | Code | When | Sentence |
  |---|---|---|
  | `LARGE_IDLE` | private ≥ `large_mb` and idle ≥ `idle_days` | `f"Big and idle: {size}, not used in {idle} of laptop use"` |
  | `IDLE` | idle ≥ `idle_days`, not large, and the app has had windows or is an instance | `f"Not used in {idle} of laptop use, holding {size}"` |
  | `LARGE` | large, not idle | `f"Using a lot of memory: {size}"` |
  | `POLLING` | instance, active in the last 10 ticks, idle ≥ 1 hour | `f"Still running and busy, but you haven't looked at it in {idle}"` |
  | `LONG_RUNNING` | instance age (now − first_seen) ≥ `long_running_days` | `f"Running for {fmt_dur(age)}"` |
  | `AUTOSTART_RARE` | has an enabled startup entry, observed days ≥ `rare_min_observed_days`, distinct used days ≤ `rare_max_days_used` | `f"Starts with Windows but you used it on only {n} of the last {d} days"` |
  | `STANDALONE` | `has_windows_ever` is False and it is not an instance (windowless, no owning app) | `f"Background service with no app you use: {desc}"`, where `desc` = `cfg.notes[key]`, else the first service description, else `"no description available"` |
  | `DUPLICATE` | 2+ apps whose labels are in the same `categories` list are present | `f"Duplicate: {n} {category} products running ({', '.join(labels)})"` |

- **Caution.** If `microsoft`, `caution = cfg.notes.get(key, "Part of Windows; turning it off may affect some features.")`. STANDALONE uses the note text as its description too.
- **Inclusion and ranking.** Include apps with ≥1 reason. Sort by `private_bytes` descending, but put apps whose only codes are `DUPLICATE` or `STANDALONE` after the rest. `reclaimable` = the sum of included `private_bytes`.
- **Service modes.** `["manual","disabled"]`, minus `"disabled"` when `dependents(svc)` is non-empty for any of the app's services.
- **Kernel note.** When `pool_nonpaged > nonpaged_warn_mb`: `f"Windows kernel memory is high ({fmt_size(nonpaged)} non-paged). This is often a driver leak; a reboot clears it. Up {fmt_dur(uptime)}."`
- **Logger.** `logger_over_cap = logger_ws > logger_cap_mb MiB`.
- **Typical memory.** `typical_private` is the median private_bytes over history.

**Interfaces:**
- Consumes: `build_report` (Task 7), `group_for_key` (Task 4), actions (Task 8), db.
- Produces:
  - `make_server(cfg: Config, conn_factory: Callable[[], sqlite3.Connection], token: str, actions_impl=actions) -> ThreadingHTTPServer`, bound to `("127.0.0.1", 0)`.
  - `serve_report(cfg: Config, open_browser: bool = True) -> None`:
    - token = `secrets.token_urlsafe(32)`
    - opens `http://127.0.0.1:<port>/?t=<token>`
    - a watchdog thread shuts the server down `heartbeat_timeout_s` after the last heartbeat (once one has been received), or after `server_idle_timeout_s` with no requests
  - `report_to_json(r: Report) -> dict`: `dataclasses.asdict`; sizes stay in bytes.
- Routes:
  - Every request must carry `Host == f"127.0.0.1:{port}"`, else 403.
  - `GET /?t=` (wrong t → 403).
  - `GET /static/<file>`: only the three static files.
  - `GET /api/report`
  - `POST /api/heartbeat`
  - `POST /api/action` with JSON `{"action":"stop"|"force"|"disable_startup"|"undo","app_key"?,"mode"?,"action_id"?}`
    - Re-resolve the group with `group_for_key(app_key)`; a missing group → `already_stopped`.
    - `disable_startup` takes the entries from `startup_entries(conn)` filtered by app_key. It never trusts entries sent by the page.
  - All `/api/*` require header `X-Memwatch-Token: <token>`, else 403. Any `Origin` header that is not `http://127.0.0.1:<port>` → 403. No CORS headers are sent at all.
  - `exclude_keys` for `build_report`: from a live `group_processes`, the app_keys of groups containing the server's own pid, its ancestor pids (the launching tree), or any process whose cmdline contains `-m memwatch` (the logger and elevated runner). Recompute this on every `/api/report`. Actions on these keys are refused with `failed` / `"memwatch will not stop itself"`.
- Page (vanilla JS; follows OS light/dark via `prefers-color-scheme`; works at narrow widths). Sections, in order:
  1. **Pressure now:** RAM used/total, commit used/limit, Memory Compression, "You could free about X", and `partial_note` if set.
  2. **Suggestions:** each card shows label, size, last used, reasons as bullet sentences, caution (amber), a "limited data" tag, and a warning `"Has open windows — unsaved work may be lost"` when `has_windows`.
     - Buttons: **Stop now**. When `startup` is non-empty: **Stop starting with Windows** (a Manual/Disabled choice when `service_modes` exist). **Force kill** appears only after a `still_open` result.
     - Every result message is shown on the card. The card re-fetches `/api/report` after each action.
  3. **All apps:** a table of label, size, inline-SVG sparkline from `spark`, last used and autostart, sortable by size.
  4. **Not fixable here:** `kernel_note`, uptime, and "memwatch logger: N MB (cap 50 MB)", shown red when `logger_over_cap`.
  5. **Undo:** each `undo` record, with an **Undo** button.
  - Heartbeat every 15 s.
